# /project-review

`git diff dev...HEAD` (커밋분)와 `git diff HEAD` (미커밋분)를 읽고 아래 순서로 점검한다. **코드를 고치지 않는다.**
변경이 없으면 "변경 없음" 한 줄로 끝낸다.

## 체크리스트
1. **정확성** — 로직 오류, 경계값(최소·최대, 빈 배열, null), 예외 처리 누락.
2. **도메인 규칙** — 앱·웹에서 도메인 계산, 불변 조건 검증 누락, 벙 정원 같은 동시 쓰기 경합.
3. **권한** — 동호회원·운영진 전용 기능을 서버에서 검사하는가, 남의 게시물·댓글·DM을 수정·조회할 수 있는 경로는 없는가.
4. **레이어 위반** — Controller 안 비즈니스 로직, Entity 외부 노출, `@Data` 사용, 서버 컴포넌트에 불필요한 `"use client"`.
5. **테스트** — 새 로직에 테스트가 있는가, 확률적 단언은 없는가, 외부 I/O를 실제로 호출하지 않는가.
6. **보안** — 입력 검증 누락, 비밀값 하드코딩, JPQL/SQL 문자열 결합, `NEXT_PUBLIC_`·`EXPO_PUBLIC_`에 비밀값, 토큰을 AsyncStorage에 저장.
7. **모바일** — iOS·Android 한쪽에서만 동작하는 코드, 네이티브 의존성을 `pnpm expo install` 없이 추가, 큰 목록 가상화 누락.
8. **규약** — `api-conventions` 응답 포맷·에러 코드 준수, 네이밍(`XxxResponse`, camelCase JSON).
9. **스타일** — `any`, 인라인 style, import 순서 등 rules 위반. 사소한 건 마지막에 한 줄로 묶는다.

## 출력 형식
심각도순(🔴 치명 / 🟠 중요 / 🟡 사소) 으로:
```
🔴 apps/api/.../MeetupService.java:42 — 정원 확인 후 저장 사이 경합 — 유니크 제약 또는 비관적 락
```
마지막 줄에 판정: **머지 가능** / **수정 후 머지** / **재작업**.
