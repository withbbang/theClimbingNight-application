# 1단계-08 배포와 출시 준비 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1단계를 NAS에 배포하고 스토어에 낼 수 있게 한다. Apple 로그인 탈퇴 시 Apple 토큰 폐기, 운영 이미지·Compose·nginx·Cloudflare Tunnel, 백업, GitHub Actions 배포, 앱 운영 빌드 설정을 만든다.

**Architecture:** k-drinker와 같은 패턴이다. `master` 푸시 → GitHub Actions가 api·web 이미지를 GHCR에 올림 → SSH로 NAS에 `deploy/` 복사 → `compose pull && up`. 외부 노출은 compose 안의 `cloudflared`가 nginx(`/api/*` → api, `/*` → web)로 넘긴다. 호스트 포트는 열지 않는다. Apple 토큰 폐기는 탈퇴할 때 앱이 Apple 재인증으로 받은 authorization code를 API에 보내고, API가 code → refresh token 교환 후 탈퇴 커밋 뒤 revoke 한다 (토큰을 DB에 저장하지 않음).

**Tech Stack:** Spring Boot 4.1.2 / Java 17, nimbus-jose-jwt 10.10(ES256 client secret), MySQL 8.4, nginx 1.28-alpine, cloudflare/cloudflared, Node 24-alpine(Next standalone), GitHub Actions(`docker/build-push-action@v6`, `appleboy/scp-action@v1`, `appleboy/ssh-action@v1`), Expo SDK 58 + EAS.

**Spec:** `docs/architecture.md` 3·5(컨테이너·메모리 예산·배포·백업)·11(푸시)·12장. 참고 구현: `~/Desktop/code/k-drinker`의 `.github/workflows/deploy.yml`, `deploy/compose.yml`, `deploy/backup.sh`, `apps/*/Dockerfile`. 규약은 `.claude/rules/{api,mobile,testing}.md`, `api-conventions` 스킬.

**이 계획에 없는 것:** `[확인 필요]` 문안 채우기(사용자가 값을 줘야 함), 도메인 구매, 스토어 등록 화면 작성, 2단계(R2 미디어·worker).

## 작업 방식

- 브랜치: `dev`에서 `feat/deploy`. 첫 커밋은 이 문서(`Docs : 배포와 출시 준비 계획 추가`). 커밋 전 `.gitmessage.txt`를 읽고, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 코드 태스크는 실패하는 테스트 → 실패 확인 → 구현 → 바뀐 앱의 lint·test(웹은 build도) → 커밋.
- `.env.example`은 그 파일만 다루는 명령으로 고친다. 실제 `deploy/.env`는 만들지 않는다.
- 도메인이 아직 없으므로 문서·예시는 `<도메인>`으로 적고 실제 값은 `deploy/.env`의 `PUBLIC_HOST`로 받는다.
- 리뷰 강도는 `medium`을 제안한다(탈퇴 흐름과 운영 설정을 바꿈). 실행 전 승인받는다.

## Global Constraints

- 새 API 환경변수: `APPLE_CLIENT_ID`(기본 `com.theclimbingnight.app`), `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY`(.p8 PEM 본문). `application.yml`·`apps/api/.env.example`·`deploy/.env.example`·`deploy/compose.yml`·`deploy/README.md` 표를 함께 고친다. 기존 키(`DB_*`, `JWT_SECRET`, `KAKAO_APP_ID`, `GOOGLE_CLIENT_IDS`, `APPLE_AUDIENCES`, `EXPO_ACCESS_TOKEN`)도 deploy에 모두 넣는다.
- `mem_limit`: nginx 32m, api 768m, web 256m, mysql 512m, cloudflared 64m. api JVM은 `-Xms128m -Xmx512m -XX:MaxMetaspaceSize=192m -XX:+UseSerialGC -XX:+ExitOnOutOfMemoryError`.
- api `stop_grace_period: 40s` (Boot 기본 graceful 종료 30초 + 여유, 15초 이상 요구 충족).
- 모든 서비스 `restart: unless-stopped`, 로그는 json-file `max-size: 10m`, `max-file: 3`, `TZ: Asia/Seoul`.
- 이미지는 `linux/amd64`(DS1520+). Dockerfile에 BuildKit 전용 문법(`--mount`, `--chmod`)을 쓰지 않는다.
- 비밀값은 명령행 인자·로그에 싣지 않는다 (MySQL 비밀번호는 `MYSQL_PWD`, 푸시 토큰·Apple 토큰 원문 로그 금지).
- 응답·에러는 `api-conventions` 스킬을 따른다. 새 에러 코드는 `AUTH_APPLE_REAUTH_REQUIRED` 하나다.

## Review Focus

1. **Apple 재인증 창을 닫는다** → 탈퇴되지 않고 탈퇴 화면에 남는다. 오류 배너도 띄우지 않는다. Task 2.
2. **Apple 계정 사용자가 다른 Apple ID로 재인증한다** → 탈퇴되지 않고 `AUTH_APPLE_REAUTH_REQUIRED`. Task 1.
3. **탈퇴는 커밋됐는데 Apple revoke가 실패(5xx·타임아웃)한다** → 탈퇴는 성공(204)으로 끝나고 경고 로그만 남는다(토큰 원문 없이). Task 1.
4. **prod에서 hikari 격리 수준 설정이 빠지거나 바뀐다** → API가 기동하지 않는다(조용히 REPEATABLE READ로 돌지 않음). Task 3.
5. **`deploy/.env`가 없거나 필수 값이 비었다** → 배포가 컨테이너를 내리기 전에 원인 이름을 찍고 멈춘다. Task 5.

**Interfaces:**
- Produces:
  - `AuthProperties.Apple(List<String> audiences, String jwksUrl, String baseUrl, String clientId, String teamId, String keyId, String privateKey)`. yml: `base-url: https://appleid.apple.com`, `client-id: ${APPLE_CLIENT_ID:com.theclimbingnight.app}`, `team-id: ${APPLE_TEAM_ID:}`, `key-id: ${APPLE_KEY_ID:}`, `private-key: ${APPLE_PRIVATE_KEY:}`.
  - `AppleClientSecret.create(): String`. ES256 JWT, header `kid=keyId`, claims `iss=teamId`, `iat=now`, `exp=now+5분`, `aud=https://appleid.apple.com`, `sub=clientId`. 키는 `JWK.parseFromPEMEncodedObjects(privateKey).toECKey()`. `Clock` 주입.
  - `AppleTokenRevoker.enabled(): boolean`. teamId·keyId·privateKey가 모두 있으면 true.
  - `AppleTokenRevoker.exchange(String authorizationCode, String expectedSubject): String`. `POST {baseUrl}/auth/token`(form: `client_id`, `client_secret`, `code`, `grant_type=authorization_code`)를 호출해 refresh token을 돌려준다. 응답 `id_token`의 `sub`는 `SignedJWT.parse`로 읽는다(Apple과 직접 TLS로 받은 응답이라 서명 재검증 생략). `sub`가 다르면 → `AUTH_APPLE_REAUTH_REQUIRED`. Apple 4xx → `AUTH_APPLE_REAUTH_REQUIRED`. 5xx·연결 실패 → `AUTH_PROVIDER_UNAVAILABLE`.
  - `AppleTokenRevoker.revoke(String refreshToken): void`. `POST {baseUrl}/auth/revoke`(form: `client_id`, `client_secret`, `token`, `token_type_hint=refresh_token`). 실패해도 던지지 않고 `log.warn("Apple 토큰 폐기 실패: status={}", ...)`만 남긴다. `socialRestClient`를 쓴다.
  - `AuthIdentityRepository.findFirstByUserId(Long userId): Optional<AuthIdentity>`
  - `AccountWithdrawalService.withdraw(long userId, @Nullable String appleAuthorizationCode): void`. 트랜잭션 없음. ① 신원이 APPLE이고 `revoker.enabled()`일 때: code가 비었으면 `AUTH_APPLE_REAUTH_REQUIRED`, 있으면 `exchange`. ② `userService.withdraw(userId)`. ③ 교환한 토큰이 있으면 `revoke`. 외부 호출은 행 잠금 트랜잭션 밖에서 한다.
  - `WithdrawRequest(String appleAuthorizationCode)`. 컨트롤러는 `@RequestBody(required = false)`로 받는다 (본문 없는 기존 DELETE도 그대로 된다).
  - `ErrorCode.AUTH_APPLE_REAUTH_REQUIRED(HttpStatus.BAD_REQUEST, "Apple 계정을 한 번 더 확인해야 탈퇴할 수 있어요.")`

구성 값:
- **mysql**: `mysql:8.4`, DB `theclimbingnight`, k-drinker와 같은 command(`utf8mb4_0900_ai_ci`, `--skip-name-resolve`, `--innodb-buffer-pool-size=128M`, `--performance-schema=OFF`, `--max-connections=50`)와 healthcheck(`MYSQL_PWD` 방식, `start_period: 300s`), 볼륨 `mysql-data`.

- **web**: Dockerfile은 k-drinker `apps/web/Dockerfile`과 같되 `API_INTERNAL_URL` 빌드 인자는 뺀다 (운영 `/api`는 nginx가 받는다). `depends_on: api (service_healthy)`.
- **nginx**: `nginx:1.28-alpine`, `default.conf` 읽기 전용 마운트. `location /api/` → `http://api:8080`, `location /` → `http://web:3000`. `client_max_body_size 2m`(API multipart 1MB보다 조금 크게). `real_ip_header CF-Connecting-IP`, `set_real_ip_from 172.16.0.0/12`. `log_format`은 `$remote_addr $time_iso8601 "$request" $status $body_bytes_sent "$http_user_agent" $request_time`로 정하고 쿼리스트링을 남기지 않게 `$request` 대신 `$request_method $uri $server_protocol`를 쓴다. `server_tokens off`. 호스트 포트는 열지 않는다.
